# JazzyDalpeng 학습과 사용자 경험 설계

기본 스케일부터 코드, 블록코드, 모드와 이론까지 배우고, 이해한 내용을 기타에서 숙달하도록 돕는 학습 앱을 설계한다. 직관적인 시각화와 소리를 연결하고, 수려한 디자인은 학습 과제와 음악적 관계를 선명하게 만드는 데 사용한다.

이 문서는 구현 전 설계 초안이다. 학습 과제와 화면 흐름은 아래 기준으로 검증하며 조정한다. 기존 캔버스 라이브러리, 음악 계산, 오디오 재생 기반은 활용한다.

## 제품의 중심

사용자가 앱을 열었을 때 오늘 익힐 내용과 첫 행동을 알 수 있어야 한다. 학습을 마치면 무엇을 이해했는지, 무엇을 연주할 수 있는지, 다음에 무엇을 연습할지가 드러나야 한다.

주요 사용 상황은 기타를 들고 짧게 반복하는 개인 연습이다. 초기 설계는 일반적인 6현 표준 튜닝을 기본으로 삼는다. 연습 시간은 사용자가 선택하며, 시간 제한을 학습 성공 조건으로 사용하지 않는다.

핵심 원칙은 다음과 같다.

- 한 과제는 확인 가능한 음악적 목표 하나를 갖는다.
- 지판 위치, 도수 관계, 소리를 함께 연결한다.
- 안내를 점차 줄이고 키와 위치를 바꾸어 익숙한 그림에 의존하는지 확인한다.
- 이해와 실제 연주 숙달을 별도로 기록한다.
- 자유 탐색 중에도 학습으로 돌아올 수 있다.
- 학습 순서는 권장 경로이며, 이미 아는 내용은 확인 후 건너뛸 수 있다.

리듬은 모든 단계에서 다룬다. 처음에는 일정한 박과 쉼표부터 시작하고, 이후 분할, 싱코페이션, 스윙으로 확장한다. 모드는 중심음과 화성 배경을 소리로 비교하도록 구성한다. 포지션 이동만으로 모드가 바뀌었다고 설명하지 않는다.

블록코드의 구체적인 범위는 상세 단원 설계에서 확정한다. 기타에서 멜로디를 최상성부로 둔 화음 연주를 출발점으로 제안하며, 보이싱 기법과 재즈 화성화 방식은 필요한 선수 개념에 따라 분리한다.

## 공통 학습 흐름

1. 발견: 짧은 소리와 조작으로 배울 관계를 경험한다.
2. 이해: 경험한 관계를 짧은 설명과 시각화로 정리한다.
3. 안내 연습: 시범, 현재 음, 다음 음을 보며 연주한다.
4. 독립 연습: 도수나 위치 표시를 줄이고 직접 찾거나 연주한다.
5. 변형과 적용: 다른 키, 위치, 리듬 또는 진행에서 사용한다.

설명과 과제는 같은 화면에서 이어진다. 진행 중 표시를 켜거나 시범을 다시 들어도 학습 상태를 유지한다. 연주 과제에서는 기타를 잡은 상태로 조작할 수 있도록 재생과 반복을 크게 제공하고, 설정 변경은 일시정지 상태에서도 가능하게 한다.

## 첫 과정의 세부 설계

첫 구현은 메이저 스케일에서 트라이어드로 이어지는 과정이다. 음과 인터벌의 최소 설명을 과정 안에서 제공하고, 더 자세한 기초 단원으로 이동할 수 있게 한다.

| 단원            | 목표                    | 인터랙션과 연습                                | 확인 기준                                  |
| --------------- | ----------------------- | ---------------------------------------------- | ------------------------------------------ |
| 음 사이의 간격  | 반음과 온음 구분        | 한 줄 위에서 음을 이동하고 두 음 듣기          | 간격을 구성하는 과제와 직접 연주 자기 평가 |
| 메이저 구조     | 온온반온온온반 이해     | C에서 시작해 다음 음을 선택하고 간격 표시 확인 | 간격 도움 없이 스케일 구성                 |
| 도수와 음 이름  | 위치와 역할 연결        | 음 이름과 도수 표시 전환, 지정 도수 찾기       | 다른 근음에서도 지정 도수 찾기             |
| 첫 포지션       | 한 범위에서 스케일 연주 | 시범, 느린 반복, 상승과 하강                   | 사용자가 안내 없이 연주 가능 여부 기록     |
| 다른 키와 위치  | 관계를 유지해 이동      | 키 변경 후 예측하고 확인, 다른 운지 비교       | 원래 위치와 다른 조건에서 수행             |
| 트라이어드      | 1도 3도 5도로 코드 구성 | 스케일에서 세 음 선택, 순차음과 화음 듣기      | 도움 없이 코드톤 선택                      |
| 다이어토닉 입문 | 스케일 안의 코드 관계   | 각 음에서 3도씩 쌓고 장단 감각 비교            | 코드 구성과 짧은 연결 연주                 |

첫 구현의 다이어토닉 설명은 트라이어드까지다. 7화음, 기능화성, 텐션은 이후 과정으로 연결한다. 운지 제안은 가능한 예시로 제시하며 손 크기와 편안한 운지에 따라 변경할 수 있게 한다.

### 예시 과제

과제 제목은 “C 메이저에서 3도를 찾아보세요”로 제시한다. 지판에는 근음과 선택 가능한 범위를 표시하고, 사용자가 음을 선택하면 해당 음을 들려준다.

다른 도수를 선택하면 선택한 음의 도수와 근음으로부터의 관계를 보여준다. 힌트는 도수 표시, 간격 표시, 정답 위치 순서로 늘어난다. 정답 확인 후에는 기타로 같은 음을 연주하는 단계와 다른 근음에서 찾는 변형 단계로 이어진다.

히든 음의 표시를 다시 켤 수 있고, 재시도에 벌점을 주지 않는다. 정답을 기억해서 누르는 것과 관계를 이해하는 것을 구분하기 위해 조건이 바뀐 과제를 함께 제공한다.

## 숙달과 복습

이해 과제는 앱에서 확인할 수 있는 답을 검증한다. 연주 과제는 초기 버전에서 자기 평가를 사용한다. 마이크 기반 자동 채점과 정확한 연주 판정은 별도 기능으로 검증한 뒤 도입 여부를 정한다.

| 기록             | 의미                           | 다음 제안               |
| ---------------- | ------------------------------ | ----------------------- |
| 접함             | 설명이나 시범을 확인함         | 안내 연습               |
| 안내와 함께 가능 | 표시를 보며 수행함             | 힌트를 줄인 연습        |
| 독립적으로 가능  | 해당 조건에서 도움 없이 수행함 | 다른 키나 위치          |
| 변형 가능        | 조건을 바꾸어 수행함           | 음악적 적용과 이후 복습 |

이해 기록과 연주 기록은 각각 보관한다. 연주 자기 평가는 “아직 어려움”, “천천히 가능”, “편하게 가능”으로 입력하며 키, 위치, 템포, 안내 사용 여부를 함께 저장한다. 학습 완료를 특정 BPM 하나로 결정하지 않는다.

오늘의 복습은 최근 어려웠던 내용과 한동안 연습하지 않은 내용을 제안한다. 사용자는 다른 연습을 선택할 수 있다. 초기 추천은 설명 가능한 규칙으로 시작하며, 복습 간격의 적절성은 실제 사용을 통해 조정한다.

연습 중 탐색 도구를 열면 현재 키와 선택 음 등 관련 조건을 전달한다. 돌아오면 원래 과제와 재생 위치를 복원하고 자동 재생은 사용자 조작으로 시작한다. 직접 URL로 단원을 열어도 선수 개념과 현재 과제의 설명을 확인할 수 있다.

기존 코드 탐색기와 메트로놈은 탐색 도구로 연결하고, 학습 화면에서도 필요한 기능을 사용할 수 있게 한다. 새 경로를 도입할 때 기존 공개 경로는 대응 화면으로 연결한다.

## 화면 흐름

### 모바일

상단에는 뒤로 이동, 단원 이름, 현재 과제를 표시한다. 페이지 스크롤을 최소화하고 한 화면에서 현재 과제와 주요 조작을 제공한다. 본문은 목표 한 문장, 지판, 현재 행동 안내 순서로 배치하고 설명과 힌트는 필요할 때 여는 패널에 제공한다. 하단의 연습 조작 영역에는 재생과 정지, 반복, 다음 과제를 제공한다. 영역이 콘텐츠를 가리지 않도록 여백과 작은 화면 대응을 확보한다.

템포, 키, 지판 범위 등은 접어서 제공하고 현재 설정 요약은 보인다. 과제 전환 버튼과 연습 재생 버튼은 모양과 문구로 구분한다. 과제 지판은 화면 폭에 맞추고, 작은 터치 영역은 별도 음 선택 버튼으로 보완한다. 전체 지판이 필요한 경우 범위 이동이나 확대와 현재 과제 범위로 돌아오는 조작을 제공한다. 작은 높이와 글자 확대에서는 내용을 잘라 숨기지 않고 필요한 스크롤을 허용한다.

### PC

가운데에는 지판과 현재 과제를 크게 배치한다. 옆에는 설명과 힌트, 아래에는 재생과 반복 조작을 둔다. 학습 지도는 접을 수 있는 탐색 영역으로 제공한다. 화면이 넓어져도 과제와 조작이 멀리 떨어지지 않도록 콘텐츠 폭을 제한한다.

### 주요 상태

- 준비 중: 음원 준비 상태와 진행 가능 여부를 표시한다.
- 준비 완료: 시작할 과제와 재생 버튼을 제공한다.
- 재생 중: 현재 음과 박을 표시하며 즉시 정지할 수 있다.
- 일시정지: 선택과 설정을 유지하고 이어서 재생하거나 처음부터 시작한다.
- 피드백: 선택한 관계와 정답 설명, 재시도와 힌트를 제공한다.
- 연습 종료: 이해 확인 결과와 연주 자기 평가를 구분해 기록한다.
- 소리 사용 불가: 오류 원인과 재시도를 제공하고 가능한 시각 과제는 유지한다.

## 시각 디자인과 접근성

기존 dalpeng 테마를 시각 디자인의 기준으로 유지한다. 흰 바탕, 인디고 강조색, primary-light, Spoqa Han Sans Neo 본문과 FinaleJazz 로고를 사용한다. 색상은 기존 테마 토큰을 공유하며 별도의 팔레트나 본문 서체를 도입하지 않는다. 기존 입력과 버튼의 스타일을 바탕으로 학습 조작을 구성하고, 대비와 가독성은 실제 화면에서 검증한다. FinaleJazz는 로고, 스케일 이름, 독립적인 음 이름과 도수, 프렛 번호에 사용한다. 코드 기호와 변화음은 기존 ChordNotation과 FinaleJazzChord의 기호 매핑을 사용한다. 한국어 설명, 피드백, 조작 문구, 템포와 상태 정보는 본문 서체를 유지한다.

근음은 테두리와 R 표기, 선택 음은 채움과 선택 표시, 현재 재생 음은 강조 링으로 구분한다. 색에만 의미를 의존하지 않는다. 음 이름과 도수는 명시적인 전환 조작으로 바꾸며 이명동음 표기는 키와 화성 문맥을 반영한다.

움직임은 음의 이동과 보이스 리딩처럼 관계를 설명할 때 사용한다. 동작 줄이기 설정에서도 같은 정보를 제공한다. 음악 박의 기준은 오디오 타이밍이며 시각적 애니메이션은 이를 따라간다.

모든 핵심 조작은 키보드와 터치로 사용할 수 있게 설계한다. 지판 선택은 포커스 가능한 음 목록과 연결하고, 선택 음과 도수를 텍스트로 확인할 수 있게 한다. 재생 중 모든 음을 화면 읽기 프로그램으로 연속 안내하지 않으며 요청 시 현재 상태를 확인하게 한다.

## 데이터와 캔버스 설계 방향

학습 내용, 과제의 음악 데이터, 연주 진행 상태, 표현 방식을 구분한다.

- 학습 단원: 목표, 선수 개념, 설명, 과제 묶음, 관련 학습.
- 음악 과제: 키, 음과 도수, 코드, 리듬, 정답 조건, 변형 조건.
- 연습 상태: 현재 과제, 힌트 수준, 템포, 재생 위치, 반복 범위.
- 학습 기록: 이해 결과, 연주 자기 평가, 수행 조건, 마지막 연습 시점.
- 표현: 지판 범위, 라벨, 강조 음, 선택 상태, 애니메이션.

동일한 음악 과제를 지판과 도수 관계도 등으로 표현할 수 있도록 구성한다. 운지는 음악적 음과 연결하되 하나의 음에 여러 위치가 있음을 모델에 반영한다. 초기 기록은 기기 로컬에 저장하고 기기 간 동기화 여부와 기록 삭제를 명확하게 안내한다. 데이터 형식은 버전과 이전 절차를 갖춘다.

캔버스 개선 우선순위는 선명한 DPR 대응, 공통 좌표 변환, 선택과 포커스 연결, 표시 레이어, 필요한 시점의 다시 그리기다. 이를 지판에서 먼저 검증하고 코드 관계와 리듬 표현으로 확장한다. 학습 화면에서 검증한 요구를 라이브러리 API로 일반화한다.

## 구현 순서와 검증

1. 첫 과정의 설명, 예제 음, 정답 조건과 선수 개념을 작성하고 음악 이론의 정확성을 검토한다.
2. 모바일과 PC에서 같은 과제를 수행하는 화면 프로토타입을 만든다.
3. 메이저 스케일의 도수 찾기부터 연주 자기 평가까지 한 흐름을 구현한다.
4. 변형 연습과 트라이어드 연결을 추가한다.
5. 실제 기타를 사용하는 연습에서 조작, 이해, 반복 흐름을 확인한다.
6. 검증한 구조를 학습 지도와 다른 단원으로 확장한다.

첫 과정의 검증 기준은 다음과 같다.

- 사용자가 설명을 읽기 전에 첫 행동을 찾을 수 있는가.
- 음 이름과 도수의 차이를 자신의 말로 설명할 수 있는가.
- 다른 키의 과제에서도 관계를 찾을 수 있는가.
- 기타를 잡은 상태에서 시작, 정지, 반복, 힌트를 사용할 수 있는가.
- 앱이 검증한 결과와 연주 자기 평가를 혼동하지 않는가.
- 작은 화면과 키보드 조작에서도 과제를 완료할 수 있는가.
- 종료 후 다음 연습과 그 이유를 이해하는가.

첫 구현 이후 실제 사용으로 확인할 항목은 설명 분량, 초보자의 선수 지식, 복습 제안 빈도, 블록코드의 세부 범위다. 이 결과에 따라 학습 단위의 크기와 순서를 조정한다.
